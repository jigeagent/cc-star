## 核心能力

### Phase 4 — Context Graph（本地知识图谱）
SQLite 递归 CTE 实现的轻量实体-关系图，零外部依赖。
- `cc-star graph search <query>` — 实体搜索 + 子图展示
- `cc-star graph trace <entity>` — 决策链回溯
- `cc-star graph stats` — 图谱统计概览
- spaCy `zh_core_web_sm` 中文 NER，离线可用

### Phase 5 — hooks.registry.json 自动恢复
解决 settings.json 被覆盖导致全系统停摆的 🔴 风险。
- 注册 hooks 时自动写入 `~/.cc-star/hooks.registry.json`
- `cc-star doctor` 检测到 hook 缺失时自动从 registry 恢复
- 保留现有设置，仅合并 hook 配置

### Phase 6 — Windows Task Scheduler 集成
- `cc-star scheduler register` — 注册凌晨 3:00 巩固任务
- `cc-star scheduler unregister` — 删除计划任务
- `cc-star scheduler status` — 查询任务状态
- 使用原生 schtasks.exe，零依赖

### Phase 7 — doctor 完整版 + 发布就绪
- `cc-star doctor --fix` — 全量自检 + 自动修复（配置/Hook/数据库/OpenViking）
- `VERSION` 文件 + `RELEASE-v0.7.0.md` 发版说明
- `__version__` 升级到 0.7.0

## 经验教训

### 1. spaCy 模型加载不能在循环里 — 代价极大

**问题：** `_import_from_sessions()` 和 `consolidate()` 都在每次 session 循环中调用 `load_spacy()`，导致模型被反复加载（~4s/次）。741 条 session 预计跑 50 分钟。

**发现过程：** 冷启动在后台跑了 5 分钟没输出，查代码发现 `load_spacy()` 在 for 循环内。写诊断脚本确认单次模型加载 4.2s、3 条 session 处理 0.0s，定位根因。

**修复：** 将 `load_spacy()` 移到循环外，冷启动从 ~50 分钟降为 ~10 秒（5000% 提速）。两条独立代码路径（`_import_from_sessions` + `consolidate`）同步修复。

**教训：** NER/ML 模型初始化必须是"加载一次→复用 N 次"的单例模式。不要在循环里调用任何模型加载函数。代码审查时专门检查"import X"或"load_X"是否在 for 循环内部。

### 2. 跨层代码依赖导致 import 路径问题

**问题：** `consolidation_worker.py` 依赖 `~/.cc-star/hooks/graph_extract.py`，使用 `sys.path.insert(0, ...)` 解决。这种隐含依赖容易断。

**修复：** 导入时同时加入 worker 和 hooks 两个路径。

**教训：** worker 脚本和 hook 脚本共用同个 NER 管线但分属不同目录，后续应把 spaCy NER 封装成 `cc_star.graph.extractor` 模块，统一从 cc_star 包导出，消除跨目录 import hack。

### 3. 定时任务的权限比想象中高

**问题：** `schtasks /ru SYSTEM` 可以让 consolidation worker 在最高权限下执行，但 worker 脚本输出的文件（日志、graph.db）归属 SYSTEM 账户，用户 `Administrator` 无法覆盖。

**教训：** 使用 `/ru SYSTEM` 方便，但要注意文件归属。如果 worker 需要写入用户家目录，用 `/ru "Users\Administrator"` 更安全。

### 4. 测试环境的兼容陷阱

**问题：** `capsys` fixture 在 pytest 9.x + Windows 环境不可用（`I/O operation on closed file`）。导致 7 个 CLI 测试一直 error，污染测试结果。

**教训：** 长期应该修，短期不影响功能测试。Windows 下的 pytest 兼容性本身不是 cc-star 的 bug，但确实增加了新测试的认知负担——每次跑测试都要先排除这 7 个已知错误。
